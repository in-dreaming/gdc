压缩算法领域过去 40 年的主线，本质上一直是：

> “如何更高效地预测下一个符号出现的概率，并以更低 bit 数编码它。”

zstd、oodle、lz4 等看似差异巨大，但底层核心其实可以拆成 4 层：

1. 数据建模（找重复 / 找模式）
2. 概率建模（预测出现概率）
3. 熵编码（把概率转成 bit）
4. 工程实现（SIMD、cache、流水线、并行、IO）

你现在是在做“特定场景的新压缩算法”预研，这非常关键，因为现代压缩算法真正的突破点已经不再是“通用压缩率”，而是：

* 特定数据分布
* 特定硬件
* 特定 IO 模式
* 特定实时性要求
* 特定更新方式（diff/streaming/chunk）

这也是 Oodle 能吊打传统通用压缩器的根本原因。

---

# 一、现代高性能压缩算法的技术谱系

现代主流 lossless 压缩，大致可以分：

| 类别                   | 代表                                  |
| -------------------- | ----------------------------------- |
| LZ 系                 | LZ4 / zstd / DEFLATE / Oodle Kraken |
| BWT 系                | bzip2                               |
| PPM / Context Mixing | zpaq / paq                          |
| ANS/FSE 系            | zstd / Oodle                        |
| Learned Compression  | Neural Compression                  |
| Domain Specific      | Texture/DNA/GamePatch               |

现在工业界真正主流：

* LZ + 熵编码
* ANS/FSE 正在替代 Huffman
* learned compression 开始进入特定领域

---

# 二、LZ4 的底层原理

## 核心目标

LZ4 的目标不是最高压缩率。

它的目标：

> “CPU cache 内极速解压。”

这是游戏/数据库/实时系统最重要的指标。

---

# 三、LZ4 数学与机制

LZ4 本质：

## 1. LZ77 滑动窗口

核心思想：

当前字符串：

```text
ABCABCABC
```

发现：

```text
ABC
```

之前出现过。

于是编码：

```text
(offset=3,length=3)
```

而不是重新存储。

这是：

## 动态字典压缩

来源：

LZ77

([ScienceDirect][1])

---

# 四、LZ4 为什么极快

关键：

## 它牺牲了：

* 搜索深度
* 最优匹配
* 熵编码
* 高级概率模型

换取：

* 极少 CPU branch
* 极少 cache miss
* SIMD 友好
* 线性扫描

---

# 五、LZ4 的核心数据结构

本质：

## 哈希表

例如：

```text
hash(4 bytes) -> 最近位置
```

压缩时：

```cpp
pos = hash(input[i:i+4])
```

找到过去相同前缀。

---

# 六、LZ4 的关键 tradeoff

| 项目                | LZ4 |
| ----------------- | --- |
| 压缩率               | 低   |
| 解压速度              | 极高  |
| branch prediction | 极友好 |
| cache locality    | 极强  |
| entropy coding    | 无   |
| latency           | 极低  |

所以：

LZ4 非常适合：

* 游戏资源 streaming
* runtime asset
* ECS chunk
* network packet
* SSD IO pipeline

---

# 七、zstd 的底层原理

Zstandard

zstd 本质：

> “LZ4 的速度 + 接近 LZMA 的压缩率”

它真正革命性的地方：

# FSE（Finite State Entropy）

这是 Yann Collet 的核心创新。

---

# 八、zstd 的技术架构

zstd：

```text
LZ77 Match Finding
    +
Sequence Encoding
    +
FSE/ANS Entropy Coding
    +
Dictionary Training
```

---

# 九、什么是 FSE / ANS

传统 Huffman：

```text
概率高 -> 短 bit
概率低 -> 长 bit
```

但：

* bit 操作复杂
* branch 多
* table decode 不够快

于是：

# ANS（Asymmetric Numeral Systems）

出现。

它是：

> “接近 arithmetic coding 压缩率，但拥有 Huffman 的速度”

这是现代压缩革命之一。

---

# 十、ANS 的数学本质

核心思想：

把：

```text
概率分布
```

映射到：

```text
整数状态机
```

编码时：

```text
state = C(state,symbol)
```

解码：

```text
symbol,state = D(state)
```

这是：

## 有限状态概率编码器

其理论本质：

* 信息论
* 状态机
* 熵极限逼近

zstd 使用：

# tANS / FSE

Finite State Entropy。

---

# 十一、为什么 FSE 极强

相比 Huffman：

| 项目             | Huffman | FSE |
| -------------- | ------- | --- |
| 压缩率            | 一般      | 更高  |
| table decode   | 一般      | 极强  |
| SIMD           | 较弱      | 强   |
| cache locality | 一般      | 强   |
| branch         | 较多      | 极少  |

这也是：

zstd 能同时：

* 快
* 压缩率高

的关键。

---

# 十二、zstd 的真正创新点

## 1. Fast Match Finder

不是简单 hash chain。

而是：

* lazy matching
* optimal parsing
* multi-length search
* repeat offset

---

## 2. Dictionary Training

这是游戏/patch 极其关键的。

zstd 支持：

# 训练字典

例如：

```text
大量 UI DSL
大量 prefab
大量 json
大量 ts script
```

训练后：

小文件压缩率会暴增。

这是游戏资源非常重要的点。 ([Reddit][2])

# 十三、Oodle 的本质

Oodle

不只是压缩率。

# 解压 throughput

```text

```

解压器成为 IO pipeline 的一部分。
